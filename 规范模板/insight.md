# 工作洞察模板

- [ ] 不超过 100 行
- [ ] 用词专业且言简意赅
- [ ] 关键信息加粗处理但别滥用
- [ ] 严格基于投喂的工作语境文档生成，不存在的内容不总结提炼
- [ ] 本文所有的复选框和有序列表内容不出现在输出中，仅为 AI 生成的约束条件

## 技术洞察




- [ ] 采用**五层问题驱动型叙事框架**，每一层承担独立功能，层与层之间形成认知递进闭环，核心手法包括：第二人称对话感、从具象到抽象的认知路径、负面警句制造紧迫感、终局思维拉升视野高度：

1. **场景钩子**：用读者亲身经历的具体困境开场，以第二人称制造代入感，将抽象议题转化为"你"的问题。
  - **硬约束**：钩子中出现的每个专有名词（工具名、流程名、角色名、项目名）必须可在原文中逐字找到。若原文未提及 `interface`、`trait`、`factory`，则这些词绝不出现在钩子中。
2. **概念框架**：迅速抛出一个简洁模型或公式，锚定全文讨论边界，降低认知负荷。
  - **硬约束**：公式中的运算符、变量名必须全部来自原文，任一项不能自己构造。
  - **正例**：原文有明确的 `spec + bylaw` 体系，你写成 `体系 = 规范 + 规章`——这叫摘取公式
  - 违例：原文只有一句修辞"好的设计不是做了多少，而是把什么挡在了外面"，你将其写成 `设计质量 = 挡在外面的总量 / 做进去的总量`——这叫编造公式，原文从未出现过此等号结构。
3. **分层拆解**：按维度或假设将问题剖开，每层遵循"假设 → 矛盾 → 解法"的三段式，逐层剥洋葱式揭示更复杂现实。落笔前须先穷举原文中所有"假设/矛盾"对，确定实际层级数量，避免漏层。
  - **硬约束**：分层拆解的维度数须显著少于原文条目数——需将条目按共性收敛为 3-5 个维度，而非逐条复述。
  - 违例：原文有 7 条原则，你写 7 个维度一一对应——这叫枚举而非洞察，不合格
4. **价值升华**：在解法之上再补一刀——"如果止步于此就亏了"，揭示更深层的增值视角
5. **收束回扣**：一句话概括核心挑战与核心价值，形成闭环记忆点

- [ ] **内容保真约束**：五层框架中的每一个逻辑步骤（钩子、公式、分层、升华、收束）都必须能在原文中找到对应的原文段落或论点——不得为了框架完整而凭空补充原文没有的逻辑环节。若原文缺少某层所需素材，宁可缺层或缩并为一句过渡，也不编造

## 分析报告

- 适用边界：最适合**方法梳理型**、**经验总结型**、**案例复盘型**技术文章；对纯参考文档或 API 手册不适用
- 匹配了**技术读者处理信息的心理模型**：

1. **代入优先于定义**：读者在感受到"这是我的问题"之后才开始接收新概念，而非先被概念轰炸。这解决了技术文章最常见的"文章对但没人读"问题。
2. **锚点降低认知负荷**：复杂领域中读者需要快速判断"这与我有关吗"，核心公式/模型充当了这一过滤器的角色，使全文信息有了坐标系。
3. **递进假设模拟认知成长**：逐层放宽假设的结构天然模拟了从简单到复杂的认知过程，读者始终能跟上作者的推理节奏。
4. **名词优于动词**：框架本质上是建模"稳定的名词"（结构、边界、关系），而非"易变的动词"（步骤、流程），这与数据契约思想一脉相承。
5. **内容优先于修辞**：分析报告的第一职责是复现原文的**内容骨架**（逻辑链、核心论点、论证路径），第二职责才是评价其**叙事手法**。禁止以修辞分析替代内容分析
6. **禁止将分析报告写成二次创作**：本节只做"拆解与归纳"，不引入原文未提及的新概念、新趋势或新建议。所有外推内容归属于后续的"趋势研究"或"对从业者的建议"节
7. **完整性检查**：分析报告需覆盖原文中所有独立维度的核心论点。若有明确的重要锚点（如理论来源、体系迁移背景、实施落地线索）被遗漏，视为不合格

## 趋势研究

- [ ] **基于原文的内生推演**：每个趋势必须有原文中的具体段落或论断作为推演起点，趋势是对原文已有方向的延伸，而非引入原文完全无关的外部赛道
- [ ] **区分"已述事实"与"推演判断"**：每个趋势下需明确标出——原文中说了什么（引用或概括）、以及这一步推演基于什么假设。读者应能分辨哪些是原文作者的判断、哪些是本文作者的展望

## 对从业者的建议

- [ ] **角色分层必须来自原文语境**：初/中/高级的划分维度必须与原文讨论的领域角色对应（如原文只讨论数据工程师，则三档均为数据工程师的不同阶段），不得强行套用不相关的职业阶梯
- [ ] **每条建议必须可回溯到原文的一个具体概念或诊断**：针对原文中明确提出的能力缺口、认知误区或方法论设计相应建议，禁止泛泛而谈"多学习""多实践"

## 输出前自检

生成全文后，逐项核对以下问题，**任一答案为"否"则必须重写该节**：

1. 场景钩子中的每一个专有名词是否都能在原文中逐字找到？（找不到→重写钩子）
2. 概念框架公式中的运算符、变量名是否全部取自原文，无一处自己构造？（自造→重写公式）
3. 分层拆解的维度数是否显著少于原文条目数，即完成了归纳而非枚举？（枚举→重写分层）
4. 价值升华的论据是否全部来自原文已述方向，未引入原文未涉及的"外部趋势"？（引入→删除后重写）
5. 分析报告是否覆盖了原文每一个独立维度的核心论点，且未引入原文不存在的新概念？（遗漏或捏造→补充或删除）
6. 趋势研究的每个趋势是否明确标注了原文锚点段落，且推演方向不脱离原文赛道？（无锚点或跑题→重写该趋势）
7. 对从业者的每一条建议是否关联了原文的一个具体概念或诊断？（找不到关联→重写该条）
