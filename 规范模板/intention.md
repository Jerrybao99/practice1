# 工作意图模板

## 格式要求

- [ ] 单文件 50 行内
- [ ] 措辞专业且简练
- [ ] 只输出当前最重要且优先级最高的 3 个关键工作意图
- [ ] 整个文档的立场：基于日志文件夹下全部文件、工作意图文件夹下全部文件、代码仓库中已有代码内容，提取如战略愿景和代码架构设计的关键信息，做出符合开发直觉的合理推测
- [ ] 背景/动机：一句话解释为何有如此意图
- [ ] 关键证据：最多引用 2 处关键证据（日志 1 处 + 代码 1 处，或仅日志/代码 2 处），证据必须与意图有直接因果支撑关系；优先选择绑定性最强的代码实体（如接口定义、核心结构体），而非外围辅助代码；禁止罗列仅"有关联"的引用
- [ ] 参考对标：可引用外部竞品、模型或开源项目作为设计参照（如 Modal、Posit Cloud），提供设计决策的外部验证锚点
- [ ] 设计实现：应控制在下一个可交付版本能完成的阶段性目标，而非跨越多个大版本的远期愿景，并优先复用代码仓库中已有的工具；必须锚定到具体的 API 端点、命令、模块或文件路径（如 `POST /blueprints/{name}/runs`），而非停留在抽象描述；鼓励内嵌关键代码/配置片段（结构体、YAML、接口定义等）以绑定可 grep 的代码符号；核心逻辑可用公式表达（如 `单价 = 执行时长 × 资源档位系数 × 是否可抢占`）
- [ ] 设计排除：明确列出故意不做的路径及简要理由（如"不做 DBU 式多档体系——账单复杂度是负资产"），减少后续返工讨论
- [ ] 设计原则：只输出最重要的 3 条原则
- [ ] 本文所有复选框内容不出现在输出中，仅为 AI 生成的约束条件

## 范例模板

```markdown

## 1. xxx

- 背景/动机：
- 关键证据：
- 参考对标：
- 设计实现：
  - **平台**：
  - **工具**：
  - 具体实现：
- 设计排除：
- 设计原则：
  1. 

```
