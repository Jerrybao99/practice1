# 量潮数据工程章程

## 第一章 总则

**第一条 制定依据**

本章程旨在建立量潮数据工程的技术规范与治理规则。

**第二条 目的**

为建立数据工程活动的统一规范，使数据处理过程可定义、可追溯、可验收，特制定本章程。

**第三条 适用范围**

本章程适用于所有基于量潮数据工程标准规范的技术活动，包括数据管道编排、数据蓝图设计、数据契约维护、数据目录管理等。

**第四条 定义**

（一）**数据管道**，指一组处理步骤的有序列表，定义数据从原始形态到最终产物的转换路径。

（二）**数据蓝图**，指组合数据契约和数据管道的完整处理方案。

（三）**数据契约**，指数据集的输入输出结构约束，描述数据"长什么样"，不关心存储位置。

（四）**数据模型**，指数据集中字段的名称、类型、含义、约束条件等结构化定义。数据契约包含数据模型。

（五）**数据目录**，指记录已接收、处理中、已交付文件的运行时元数据。

（五）**数据卷**，指数据目录中记录的一个文件及关联元数据，包含路径、大小、状态、来源等信息。

## 第二章 数据管道

**第五条 定义规则**

数据管道由一组有序步骤构成，每步指定一个可执行命令。管道定义采用 CUE 格式。

**第六条 步骤约束**

（一）每步应只完成一个数据转换操作，职责单一；
（二）上一步的输出即为下一步的输入，步骤间不得跨级引用；
（三）最后一步的输出即为管道最终产物。

**第七条 血缘记录**

数据管道的每一步执行须记录血缘信息，包括：

（一）输入数据名称与来源；
（二）执行命令与参数；
（三）输出数据名称与路径；
（四）执行时间与执行人。

血缘记录应当与数据集一同交付。

## 第三章 数据蓝图

**第八条 定位**

数据蓝图是完整处理方案的定义，组合一个数据契约和一个数据管道：

- 数据契约定义输入输出约束
- 数据管道定义处理步骤

**第九条 设计流程**

数据蓝图应遵循以下流程：

（一）分析业务需求，确定输入数据结构与输出数据结构，撰写数据契约；
（二）设计处理步骤，编排数据管道；
（三）组合数据契约与数据管道为数据蓝图；
（四）数据蓝图的定义存储为 CUE 格式。

**第十条 验收标准**

数据蓝图的技术验收以 CUE 定义为准，业务验收以 HTML 产物为准。

## 第四章 数据契约

**第十一条 定义规则**

每个对外交付的数据集须有明确的数据契约，包含数据集名称、字段定义、约束条件。数据契约不关心物理存储位置，只描述结构约束。

**第十二条 数据模型变更**

数据模型发生变更时，须遵循以下规则：

（一）新增字段不得破坏已有字段的语义；
（二）删除或修改已有字段须提前通知所有消费方；
（三）不兼容变更须升级数据契约版本。

## 第五章 数据目录

**第十三条 注册规则**

每次数据接收完成后，应自动向数据目录注册一条数据卷记录。记录包含文件路径、大小、接收时间、状态、来源等信息。

**第十四条 数据卷状态流转**

数据卷状态按以下顺序流转：

```
received → processing → processed → delivered
```

（一）**received**：文件已接收并注册，待处理；
（二）**processing**：正在被数据管道处理；
（三）**processed**：数据处理完成，待交付；
（四）**delivered**：已交付给客户或消费方。

状态变更须记录变更时间，不可跳过中间状态。

**第十五条 清理规则**

已标记为 delivered 的 数据卷 可按策略清理。清理策略由各项目自行定义，但须在清理前确认消费方已完成数据获取。

## 第六章 命名规范

**第十六条 Unix 风格命名**

所有目录和配置字段遵循 Unix 风格命名：

（一）**单数** — 目录名用单数，表示"这一类对象的定义"；
（二）**小写** — 全小写字母；
（三）**连字符** — 单词间用连字符分隔；
（四）**无缩写** — 除非是通用缩写，否则不缩写。

## 第七章 跨领域边界

**第十七条 领域交叉识别**

数据工程活动可能与其他工程领域产生交叉。当一项活动同时涉及多个领域时，应当首先识别各领域的边界：

（一）**数据工程与知识工程的交叉**：数据处理流程中涉及从非结构化文本提取结构化知识的，知识提取部分适用知识工程章程，数据处理部分适用本章程。

（二）**数据工程与产品研发的交叉**：数据契约的变更影响产品端开发的，产品端适配适用产品研发章程，数据契约的维护适用本章程。

（三）**数据工程与 DevOps 的交叉**：数据管道的发布涉及版本管理时，发布流程适用 DevOps 章程，数据管道定义适用本章程。

**第十八条 争议解决**

跨领域活动中出现边界冲突时，由涉及各领域的责任人协商解决。无法达成一致的，提交技术负责人裁定。

## 第八章 附则

**第十九条 章程效力**

本章程经审议通过，自发布之日起生效。

**第二十条 解释权**

本章程之解释，应遵循可追溯之基本原则。各项条文不得被解释为阻碍合理的数据工程创新或为数据交付设置不必要的障碍。
